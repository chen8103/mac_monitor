# Mac 系统负载面板设计

> 已发布应用是菜单栏 popover，当前行为以仓库根目录 [README](../../../README.md) 为准。下文是最初的独立窗口方案；「首版不做菜单栏、支持拖动缩放和置顶」不再描述现有产品。

## 目标

制作一个原生 macOS 桌面小工具，以明快、浅色的小组件风格实时展示本机系统负载。用户打开应用后，无需配置即可看到主机名、系统运行时间、CPU 总占用与逐核心负载、内存使用量和系统信息。

## 范围与成功标准

- 默认每 3 秒自动刷新，数据来自当前 Mac，而非模拟数据。
- 展示主机名、格式化运行时间、CPU 总占用率、逻辑核心数、1/5/15 分钟平均负载、逐核心占用率、已用/总物理内存、macOS 内核版本和硬件架构。
- 使用暖白背景、深灰文字、浅灰轨道与分割线；CPU 正常状态使用蓝色，内存使用青绿色，高负载使用橙色或珊瑚红。
- 窗口采用圆角和轻微阴影，信息布局参考用户提供的面板，支持拖动、调整大小、置顶切换和正常退出。
- 提供一键构建脚本，生成可双击启动的 `.app`，不要求用户安装第三方依赖。
- 首版不包含历史曲线、进程列表、告警、设置页、菜单栏驻留或开机启动。

## 技术方案

使用 SwiftUI 构建界面，AppKit 补充窗口行为，Darwin 系统接口采集指标。项目采用 Swift Package Manager 可执行目标，并通过构建脚本生成标准应用包。本机已有 Swift 6.2 和 Command Line Tools，无需引入第三方依赖。

选择原生方案是因为其资源占用和分发体积小，适合需要持续刷新的小工具；终端界面无法达到目标视觉效果，Electron 则会引入不必要的大型运行时。

## 组件与职责

### `SystemMetricsSampler`

只负责读取系统状态并输出不可变快照：

- 通过 `host_processor_info` 获取逐核心 CPU tick，以前后两次采样的差值计算每个核心及总体的使用百分比。第一次采样没有差值时显示等待状态，不伪造为 0%。
- 通过 `getloadavg` 获取 1/5/15 分钟平均负载。
- 通过 `host_statistics64` 和 `sysctl` 获取内存页统计、页大小与物理内存总量；内存使用量采用活跃页、有线（wired）页和压缩器实际占用页的合计，不包含空闲页、非活跃缓存或可回收缓存，避免与“已用内存”语义混淆。
- 通过 `sysctl` 获取逻辑核心数、内核版本和硬件架构，通过 `ProcessInfo` 获取主机名与系统运行时间。
- 将 Mach 内核接口返回的调用失败转换成明确错误，不让采样失败导致应用崩溃。

### `MetricsStore`

负责生命周期和界面状态：启动采样、维护上一次 CPU tick、每 3 秒请求快照、向主线程发布最新结果，并在视图消失时停止任务。静态信息与动态指标分开处理，避免每次刷新重复读取不变字段。

### `MonitorView`

只负责排版和展示：

- 顶部显示主机名及运行时间。
- CPU 区域显示总百分比、总进度条、核心数与平均负载，以及自适应排列的逐核心进度条。
- 内存区域显示已用/总 GiB 和总进度条。
- 底部显示 Darwin 版本、架构和“3s 刷新”。
- 百分比统一限制在 0–100%，数值使用固定小数位，避免刷新时布局跳动；逐核心条使用统一配色阈值。

### `AppDelegate` / 窗口配置

设置合理的初始尺寸与最小尺寸，保留系统标准窗口的拖动、缩放和关闭行为。通过窗口层级切换提供“置顶”能力，并提供简单退出入口。

## 数据流

1. 应用启动后，`MetricsStore` 读取静态信息并开始首次 CPU 采样。
2. 后台采样器读取系统状态，返回快照；CPU 使用率由相邻快照的 tick 差值计算。
3. 最新快照发布到主线程，SwiftUI 更新进度条和文本。
4. 定时器每 3 秒触发下一次采样；窗口关闭或应用退出时取消任务并释放定时器。

采样在后台执行，界面更新只在主线程执行。下一次采样不会因界面重绘被重复触发。

## 视觉规则

- 背景使用接近白色的暖色，主要文字使用高对比深灰，次要文字使用中灰。
- 圆角面板配合轻阴影，不使用大面积渐变或装饰性图形。
- CPU 总条和逐核心条以蓝色为主，内存条以青绿色为主。
- 总 CPU 或逐核心负载达到 70% 时使用橙色，达到 90% 时使用珊瑚红；内存使用率达到 80% 时使用橙色，达到 90% 时使用珊瑚红。
- 轨道和分割线使用浅灰，确保彩色数据清晰但不刺眼。
- 窗口变窄时减少每行核心条数量，关键数据不得被截断。

## 错误处理与边界情况

- 首次 CPU 样本尚未形成时，CPU 百分比显示为 `—`，其余可用指标正常显示。
- 单次动态采样失败时保留最近一次成功快照，并在底部显示简短错误状态；后续采样自动恢复。
- 内存总量为零、CPU tick 差值为零或数值异常时，不回退为无穷值或负值，而是显示不可用状态。
- 运行时间按天、小时、分钟格式化，避免只显示天数造成近期运行信息不明确。
- 内存统一按 GiB（1024³ 字节）换算。

## 验证

- 构建脚本成功生成应用包，应用能够在本机双击启动。
- 窗口实际展示本机主机名、核心数、内存总量、Darwin 版本和 arm64 架构。
- 连续观察至少三个刷新周期，确认 CPU、负载和运行时间更新，界面无卡死。
- 对采样与格式化逻辑进行自动化测试，覆盖首次采样、CPU tick 差值、百分比边界、阈值颜色和运行时间格式。
- 通过系统活动监视器及命令行工具交叉检查指标，允许采样时刻和内存统计口径造成合理差异。
- 实际验证窗口拖动、缩放、置顶、关闭和退出。
